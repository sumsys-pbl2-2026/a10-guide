### GitHub Flowの練習（30分）

- README.md ファイルにグループメンバーの名前を書きましょう

以下の手順を踏んでドキュメントを完成させましょう。

- レポジトリのクローン
- ブランチの作成 (git branch ブランチ名、git checkout ブランチ名）
- ファイルの編集
- ファイルのステージング（git add）
- コミット（git commit）
- リモートレポジトリへのプッシュ(git push origin ブランチ名）
- プルリクエスト（Pull Request）送信〜GitHubのWebインタフェースから
- 他の⼈がレビューをしてコメントする
- マージ

---
### Round 1（40分）

お題に従ってガイドguide.mdを作成しましょう。フォーマットはMarkdownです。内容は⾃由です。以下の時間配分で作業をして下さい。

- 計画（10分）
- 執筆（20分）
- 振り返り（10分）

- Markdownの使用方法については、この[文書](https://qiita.com/oreo/items/82183bfbaac69971917f)を参考にしてください。
- mainブランチへの直接pushは禁⽌します。
- 35分後にmainブランチにコミットされpushされたものがこの時点の成果物です。
- mainブランチにマージする前に、必ずレビューを経るようにすること。
- 「振り返り」の段階では、内容の振り返り（コンテンツで修正したい点や追加したい点を洗い出しましょう）と、進め⽅の振り返り（良かったこと， 発⽣した問題点， Round2で取り⼊れたいチームルールなど）を行います。

-----
### Round 2（40分）

Round1の振り返りを踏まえて、ガイドを改良しましょう。
作業を進めるに当たっては、作業の⾒える化を図りましょう。つまり、Round 2で行うべきタスクをissueに書き出し、各コミットメッセージをissueに対応づけるようにしてください。

- 計画（10分）
- 執筆（20分）
- 全体振り返り(10分)

最終的な編集の結果をGitHubのmainブランチにマージしてください。これに対して、タグsubmitを付けて、pushして下さい。
submitタグのついたGitHub上のmainブランチのguide.mdが最終成果物となります。

-----
### 発⽣しそうな事例とその対処
